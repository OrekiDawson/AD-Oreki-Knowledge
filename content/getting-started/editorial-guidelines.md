# 知识库编写规范

本知识库采用接近中文百科全书的写法：**准确、客观、通俗易懂、可以查证，并以简体中文呈现。** 网站主要供人阅读，不应让复杂的构建日志、英文缩写或模型生成的清单代替完整解释。

本页是读者版说明。正式编辑规则以 GitHub 中的[《知识库内容质量标准》](https://github.com/OrekiDawson/AD-Oreki-Knowledge/blob/main/docs/CONTENT_QUALITY.md)为准，编辑文章可以参考[中文知识条目模板](https://github.com/OrekiDawson/AD-Oreki-Knowledge/blob/main/docs/ARTICLE_TEMPLATE.md)。

## 如何写一篇好懂的条目

先用一段**导语**解释主题是什么、为什么重要，再按背景、工作原理、实际结果和验证方式展开。第一次使用“二进制接口（ABI）”等术语时说明含义，而不是默认每位读者都能理解。

标题、正文、图注、表头和说明文字使用简体中文。Kotlin、GitHub、源码符号、文件路径、哈希值等真实技术名称保留原拼写，并辅以中文解释。

正文以自然段为主。表格用于比较，列表用于步骤；不把整篇文章写成项目周报或检查清单。

## 什么样的事实可以写

重要结论必须附上可点击的来源，最好直接链接到固定版本的源码、报告、PR 或测试记录。

将**已验证的事实、来源作者的声明、推断、待核实问题和已推翻的旧结论**清楚区分。旧结论发生变化时，交代原因与证据，而不是悄悄删除。

例如，某个 Android 候选“能够正常自动存档”并不意味着“已经在 180 分钟内完成游戏”，也不意味着“符合正式发布条件”。这三个结论需要分别验证。

## 正文与 AI 的分工

一篇文章的绝大多数篇幅应该由通俗且严谨的中文正文构成。末尾可以设置 **“供 AI 检索（简要摘要）”**，只保留约五行结构化信息，帮助 AI 快速定位主题、当前事实、证据和适用范围。

这段摘要不能取代正文和原始证据，也不能包含要求 AI 忽略规则、执行命令或推断不存在事实的指令。

## 如何更新

新的技术结论通过正常 GitHub PR 审核。未审核的 AI 草稿只能存于仓库的隔离目录，不进入公开知识库的页面、全文搜索或 AI 问答。

本知识库不以文章数量、字数或知识图谱节点数衡量质量。**宁可少一篇，也不发布无法核实的技术结论。**
